# lhg-bp-input：项目信息采集方法论

> 目标：BP 写得烂，90% 是信息没问全就开写。本 skill 解决"问什么、怎么问、问到什么程度算齐"。
> 核心纪律：**信息卡没填满，不许进入写作阶段**。

## 1. 何时使用

- `/lhg-bp:bp` 的 Phase 0 → 全程按本 skill 执行
- 用户说"帮我写个 BP"但只给了一句话 → 先走第 3 节追问清单
- 用户给了长篇资料 → 走第 4 节提炼，缺的信息照样追问

## 2. 输入与输出

- **输入**：一句话项目描述 / 项目资料（文档、官网、聊天记录）
- **输出**：项目信息卡（第 5 节模板），每项标 [已确认] / [待补充]
- **不输出**：BP 正文——那是 lhg-bp-structure 的事

### 信息齐的定义
五大块（痛点、用户、产品、钱、团队）每块至少有一个**可验证的事实**（不是感觉）。
"市场很大"不算事实；"目标用户是 25-35 岁年轻妈妈，社区问卷 412 份里 72% 愿意付费"算。

## 3. 五问追问清单（一次问 ≤5 个）

### Q1 痛点：用户现在怎么解决这个问题的？
- 追问："没有你们的产品，用户今天用什么凑合？凑合的代价是什么？"
- 要掏出的事实：现有替代方案 + 它的缺点（贵/慢/难用），最好有用户原话。
- ❌ "用户需要更好的生鲜" → ✅ "用户现在去菜市场，痛点是品控不稳定、缺斤短两"

### Q2 用户：第一批为你付钱的是谁？
- 追问："描述一个具体的人：年龄、职业、住哪、为什么是他先买？"
- 要掏出的事实：画像越具体越好；如果有种子用户，要数量和反馈。
- ❌ "年轻人都需要" → ✅ "二线城市 25-35 岁双职工家庭，试点 200 户复购率 61%"

### Q3 收费：钱从哪来？
- 追问："用户为什么愿意付钱？收多少钱？这个价格他对比的是什么？"
- 要掏出的事实：收费模式（差价/订阅/广告）、价格、用户对比的锚点。
- ❌ "以后再想商业模式" → 天使轮可以模糊，A 轮必须有答案

### Q4 团队：为什么是你们能做成？
- 追问："创始人过去做过最相关的事是什么？团队还缺哪个关键角色？"
- 要掏出的事实：每人一句话履历 + 与项目的相关性；缺的角色如实写 [待补充]。
- 投资人看团队 > 看项目，这块不许编——编履历是融资红线。

### Q5 融资：要多少钱，干什么？
- 追问："融多少？出让多少？这笔钱花完要达到什么里程碑？"
- 要掏出的事实：金额、出让比例、资金用途、里程碑（开多少店/做到多少营收）。

### 追问话术三原则
1. **一次 ≤5 个问题**：问题轰炸会把小白问跑，分两轮问完。
2. **每个问题给例子**：小白不知道"痛点"是什么，举例"比如用户现在用什么凑合"。
3. **接受"不知道"**：不知道就标 [待补充]，不许逼用户编，更不许自己编。

## 4. 资料输入的提炼三步

1. **找事实**：把资料里带数字、人名、时间、地点的句子圈出来——这是信息卡的砖。
2. **找缺口**：对照第 5 节模板，缺哪块标 [待补充]，进追问清单。
3. **找矛盾**：资料里同一个数字有两个版本 → 先问用户以哪个为准，不许自己挑一个。

### 追问的第二轮：深挖证据（第一轮问完后）

第一轮拿到框架，第二轮要证据。每个 [已确认] 的事实追问一句"证据在哪"：

1. **痛点证据**："你怎么知道用户真痛？有用户原话、投诉、数据吗？"
2. **付费证据**："有人付过钱吗？付了多少？没付过的话，做过付费意愿测试吗？"
3. **团队证据**："履历里和这个项目最相关的成就是哪一件？能量化吗？"
4. **市场证据**："市场规模数字从哪来的？报告名、年份、口径能说出来吗？"

第二轮话术：不说"你这个不行"，说"投资人一定会问这个，我们先准备好答案"——
把追问包装成"帮你过投资人那一关"，小白配合度翻倍。

## 5. 信息卡模板

```markdown
## 项目信息卡（<项目名>，<日期>）

### 一句话
<30 秒电梯演讲：给谁、解决什么、怎么解决>

### 痛点 [已确认/待补充]
- 现有替代方案：
- 它的缺点（用户原话优先）：

### 用户 [已确认/待补充]
- 画像（越具体越好）：
- 种子用户/数据：

### 产品 [已确认/待补充]
- 一句话方案：
- 核心差异（和替代方案比）：

### 钱 [已确认/待补充]
- 收费模式与价格：
- 融资需求（金额/出让/用途/里程碑）：

### 团队 [已确认/待补充]
- 创始人履历（相关性）：
- 缺的关键角色：

### 市场线索 [已确认/待补充]
- 市场规模数字（来源+年份+口径）：
```

### 信息卡缺口处理规则

- [待补充] ≤ 3 个 → 边写边标，正文保留标记，写完统一输出 [待补充] 清单给用户。
- [待补充] 4-8 个 → 先写能写的章节，缺口章节只写框架+标记，不许编内容凑数。
- [待补充] > 8 个 → 打回：信息太少，写出的 BP 会是空架子。明确告诉用户缺什么、去哪找。

### 特殊项目的信息卡加项

- **硬件项目**：加"供应链"（谁代工、成本结构）、"认证"（3C/CE 进度）。
- **出海项目**：加"目标市场"（国家、法规、本地化）、"汇率/回款"假设。
- **SaaS 项目**：加"获客"（CAC、渠道）、"留存"（NDR/流失率）。
- 加项缺失 → 在信息卡里单列 [待补充]，不混入通用五问。

## 6. 项目信息卡模板（续：填写示例）

> 示例（社区生鲜项目）：
> - 一句话：30 分钟送达的社区生鲜前置仓，算法把损耗率打到 5% 以内
> - 痛点：菜市场品控不稳定（用户原话："早上买的菜晚上就蔫了"）
> - 用户：二线城市 25-35 岁双职工家庭；试点 200 户，复购 61% [已确认]
> - 收费：商品差价（毛利率 22%）+ 199 元/年会员 [已确认]
> - 团队：创始人前盒马区域运营 8 年 [已确认]；缺：专职财务 [待补充]
> - 融资：2000 万 / 出让 10% / 18 个月开 40 仓 [已确认]

## 7. 常见误区（反模式）

- ❌ 用户说"市场很大"，你就写"万亿市场"——"很大"不是数字，追问来源或标 [待补充]
- ❌ 一次问 15 个问题——小白直接放弃，分两轮
- ❌ 用户说"不知道"，你帮他编一个"合理的"——这是 BP 最大的雷，编的数据会在尽调时爆炸
- ❌ 跳过团队问题（觉得伤感情）——投资人第一个看的就是团队，躲不掉
- ❌ 信息卡不写 [待补充] 标记——没标记的缺口会在写作时被"顺手编上"

## 8. 自检与反馈

信息卡输出后：

1. 五大块是否每块都有 [已确认]/[待补充] 标记？→ 没标记不算做完
2. [待补充] 超过一半？→ 打回继续问，或明确告诉用户"信息太少，BP 会很空"
3. 每个 [已确认] 的事实都能说出"谁说的/哪来的"吗？→ 说不出就是编的，改成 [待补充]
4. 一句话电梯演讲写出来了吗？→ 写不出说明你还没吃透项目

反馈渠道：以 `[QC] <一句话问题>` 为标题提交到 https://github.com/lhg-plugs/lhg-bp/issues，
正文写清"场景 → 采集问题 → 期望"。好的追问话术（如针对硬件/出海项目的专用问题）也欢迎贡献。
